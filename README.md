## 1. 项目概述

本项目旨在构建一个面向专业领域（教育、医疗、法律）的**多级查询增强 RAG 系统**。传统 RAG 系统在处理复杂推理时往往由于“一刀切”的检索逻辑导致准确率低下，本项目通过引入查询分类器（L1-L4），实现精准的知识路由与混合检索。

### 设计理念 (Design Philosophy)

> **核心定位：从工程实战到学术落地的闭环**
> 
> 本项目不仅是一个问答工具，更是一个 RAG 技术全链路的实战平台。通过将“分类逻辑”与“混合检索”深度耦合，我们试图解决大模型在专业场景下的“幻觉”问题，同时满足学术论文对创新性的要求（如多级查询理解机制）。

## 2. 核心特点

本项目不仅实现了基础的 RAG 流程，更针对面试考点与学术前沿集成了以下特性：

#### 1️⃣ 意图驱动的路由机制 (Intent-Driven Routing)
系统不再盲目检索。通过微调分类模型或高性能 Prompt 策略，将用户提问分为：
- **L1 显性事实**：直接检索，快速响应。
- **L2 隐性事实**：多跳关联，挖掘深度上下文。
- **L3 可解释原理**：引入图结构检索，构建逻辑链。
- **L4 隐藏原理**：递归摘要与全局理解，应对极高难度推理。

#### 2️⃣ 混合检索与重排序 (Hybrid Search & Reranking)
结合了 **BM25 (关键字精度)** 与 **Vector (语义广度)** 的优势，并接入 Reranker 模型进行二次精选，确保召回的每一个 Chunk 都是“黄金上下文”。

#### 3️⃣ 工业级部署方案
采用本地服务器（AutoDL/实验室服务器）+ Docker 容器化技术，支持流式输出 (Streaming) 与引用溯源 (Citations)。

## 3. 技术选型

| 维度 | 技术组件 | 选择理由 |
| :--- | :--- | :--- |
| **底层框架** | LangChain / LlamaIndex | 成熟的 RAG 编排生态，支持复杂 Chain 逻辑 |
| **大语言模型** | Qwen-7B-Chat / Llama-3-8B | 兼顾性能与本地显存容量（24G 显存首选） |
| **向量嵌入** | BGE-Large-zh-v1.5 | 中文语义评测榜单（C-MTEB）长期领先 |
| **向量数据库** | FAISS (GPU 版本) | 毫秒级大规模向量检索，支持持久化存储 |
| **推理加速** | vLLM / Flash-Attention 2 | 提升多用户并发请求下的响应速度 |
| **前端交互** | Streamlit | 快速构建可视化 Demo，支持溯源高亮显示 |

### 4.2 核心模块说明

#### A. 查询预处理模块 (Query Processor)
- **输入**：原始 Query。
- **功能**：进行 Query 脱敏、纠错及 **L1-L4 分类标签预测**。
- **输出**：带标签的增强 Query。

#### B. 混合检索引擎 (Hybrid Retriever)
- **Path 1 (Vector)**：利用 FAISS 进行语义相似度计算。
- **Path 2 (BM25)**：针对专业名词进行稀疏检索。
- **Path 3 (GraphRAG)**：针对 L3/L4 级别，利用知识图谱或 RAPTOR 树状索引进行全局召回。

#### C. 生成与溯源模块 (Generator & Source Tracer)
- **功能**：将检索内容注入精心设计的 System Prompt。
- **约束**：强制 LLM 输出参考文档序号，实现“所言皆有据”。

## 5. 关键技术路线

1. **环境部署**：
   - 租用 RTX 4090 服务器，配置 CUDA 环境。
   - 使用 VS Code Remote-SSH 进行远程代码调试。
2. **数据处理**：
   - 针对不同格式（PDF/DOCX）进行结构化清洗。
   - 采用 `RecursiveCharacterTextSplitter` 进行语义切块。
3. **Pipeline 联调**：
   - 编写分类路由逻辑 -> 封装检索接口 -> 接入 LLM 推理接口。

## 6. 测试与实验方案

### 6.1 评测指标
- **检索阶段**：Hit Rate @K, MRR。
- **生成阶段**：使用 RAGAS 评测 Faithfulness (信实度) 与 Relevance (相关性)。
- **系统性能**：首字延迟 (TTFT) 与 每秒 Token 数。

### 6.2 实验对比
- **Baseline**：单纯向量检索 (Naive RAG)。
- **Ours**：多级意图路由 + 混合检索 (Proposed RAG)。
